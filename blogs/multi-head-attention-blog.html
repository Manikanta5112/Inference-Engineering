attention mechanics · from scratch

Multi-head attention,
one head at a time

A single attention head is one similarity space. Language needs many at once — syntax, coreference, position, topic. Here's the arithmetic, the split across heads, and the split across GPUs, worked through with real numbers.

~14 min read worked example: Llama‑3‑8B, H=32, D=128 no hand-waving
01 — the job attention does

Every token needs to borrow context from every other token

Attention's job, in one sentence: for every token, build a new representation that's a weighted blend of every token's information — including its own — where the weights say "how relevant is token j to understanding token i right now."

Take a 3‑token sentence, "The cat sat," each token embedded as a 4‑dimensional vector (real models use d=4096 or more — we're using 4 so every number is checkable by hand).

x1 = [1, 0, 1, 0]   // "The"
x2 = [0, 1, 0, 1]   // "cat"
x3 = [1, 1, 0, 0]   // "sat"

X = stack(x1, x2, x3)   // shape (N=3, d=4)

Everything from here is one question, asked three ways: what am I looking for, what do I contain, and what do I actually offer if picked? Those three questions are Q, K, and V.

02 — single-head attention, worked in full

Q, K, V — and the four steps between them

Step 1 — project

Multiply X by three learned weight matrices, each shape d×d = 4×4:

Q = X · Wq   shape (3,4)   "what am I looking for?"
K = X · Wk   shape (3,4)   "what do I contain?"
V = X · Wv   shape (3,4)   "what do I actually offer?"

Step 2 — score every token against every other: Q·KT

Dot Q[i] against K[j] for every pair — one matmul does all 9 pairs at once:

Q·Kᵀ → shape (N,N) = (3,3). One score per token pair.

Step 3 — softmax each row

Turn row 1's raw scores [2.1, 0.3, 1.0] into weights that sum to 1:

softmax(row 1) → [0.55, 0.10, 0.35]

Reading this: to build the new representation for "The," pull 55% from itself, 10% from "cat," 35% from "sat."

Step 4 — weighted sum of V

Output[1] = 0.55·V1 + 0.10·V2 + 0.35·V3

Repeat for all 3 rows → final output shape (3,4), same shape as the input, but now every token carries a blend of context.

the whole pipeline in one line

Output = softmax(Q · Kᵀ) · V — projection, score, normalize, blend. Multi-head does not change this pipeline. It runs it more than once, on smaller slices, in parallel.

03 — the limit of one head

One head, one similarity space

With a single head, the model has exactly one 4‑dimensional space to decide "how relevant is token j to token i." But language carries many independent kinds of relationships at once between the same two tokens — is this the subject of that verb, does this pronoun refer back to that noun, are these two words on the same topic, are they simply near each other — and one similarity score per pair can't represent all of those simultaneously without them interfering with each other.

The fix isn't a bigger single head. It's several smaller heads running side by side, each free to specialize in a different kind of relationship.

04 — multi-head attention, mechanically

Same pipeline, run H times on smaller slices

Split the model dimension d into H heads, each of size D = d / H. The constraint is simple: the H slices have to add back up to d.

D = d / H is just how you carve the vector before running attention H times.

Nothing about the math changes per head — it's the identical softmax(Q·Kᵀ)·V from Section 2, just on a 128‑wide slice instead of a 4096‑wide one. What differs is what each head learns to notice, because each has its own Wq/Wk/Wv slice and therefore its own gradient signal during training.

05 — where the GPUs come in

Does all of this run on one GPU?

Depends on the model. If the weights, KV cache, and activations fit in one GPU's memory, everything above — every head, every layer — runs on that single chip. That's the right mental model while learning the mechanics. But past a certain model size, or when throughput matters, the work gets split across GPUs. Three splits show up in practice, and only one of them is really about attention heads.

Tensor parallelism — splits inside one attention layer

This is the direct payoff of head-splitting. Because each head computes independently — it doesn't need any other head's numbers until the final concat — you can physically place different heads on different GPUs.

4-way tensor parallelism on Llama-3-8B: 32 heads ÷ 4 GPUs = 8 heads per GPU.

Each GPU only ever needs its own heads' Q/K/V slices and its own 1/4 of the KV cache. The only cross-GPU communication is a brief sync at the end of the attention block, to concatenate the per-GPU outputs before the shared Wo projection. This is exactly why multi-head attention is convenient hardware-wise — the head boundary is a natural place to cut, since heads don't depend on each other mid-computation.

Pipeline parallelism — splits across layers, not heads

Different GPUs hold different transformer layers — GPU 0 holds layers 1–16, GPU 1 holds layers 17–32 — and activations get handed off GPU‑to‑GPU as data flows through the model's depth. Within any one GPU's layers, all heads for that layer are computed together, in full, on that one chip.

Data / batch parallelism — splits across requests, not the model

Every GPU (or GPU group) runs a full copy of the model and handles different users independently. This is the "batching" lever from the roofline chart — more requests sharing a weight-load — extended across separate machines so many users can be served concurrently.

the distinction that matters

Tensor parallelism is the only one of the three that touches the head-splitting you just learned. Pipeline parallelism cuts by depth (layers). Data parallelism cuts by request (batch). All three can run simultaneously in a real cluster — a 70B+ model commonly uses all three at once.

06 — carry this forward

The five facts worth keeping

01 · the pipeline
softmax(Q·Kᵀ)·V is the whole mechanism — single-head or multi-head, it's identical.
02 · D = d / H
The H head-slices must sum back to d. Llama‑3‑8B: 4096 = 32 × 128.
03 · why H heads
One head = one similarity space. Multiple heads let the model track several relationships between the same two tokens at once.
04 · heads are independent
No head needs another head's numbers until the final concat + Wo — which is exactly what makes them splittable.
05 · tensor parallelism
Splits heads across GPUs. Different from pipeline parallelism (splits layers) and data parallelism (splits requests).
06 · single GPU is the default
Multi-GPU splitting only kicks in once a model's weights + KV cache stop fitting comfortably on one chip.
