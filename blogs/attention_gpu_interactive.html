Phase 1: Prefill (Prompt Ingestion)

Compute-Bound (GEMM)

The GPU processes the entire prompt of 6 tokens simultaneously in parallel using Matrix-Matrix Multiplications (GEMM).

Prefill Step-by-Step Breakdown

  1. Linear Projections: $$Q = X W_Q \ (6 imes 4), \quad K = X W_K \ (6 imes 4), \quad V = X W_V \ (6 imes 4)$$
  2. Attention Scores ($S$): $$S = Q K^T \implies (6 imes 4) imes (4 imes 6) = \mathbf{6 imes 6}$$ All $36$ interaction pairs are computed concurrently across GPU Tensor Cores.
  3. Context Output ($ ext{Out}$): $$ ext{Out} = ext{Softmax}\left( rac{S}{\sqrt{d}} ight) V \implies (6 imes 6) imes (6 imes 4) = \mathbf{6 imes 4}$$

Phase 2: Autoregressive Decode (Token #7)

Memory-Bandwidth Bound (GEMV)

Token generation occurs sequentially. To generate token #7, only the new token vector is projected, while past keys and values are retrieved from the KV Cache.

KV Caching & Generation Math

  • Projections for Token #7: $q_7 = x_7 W_Q$, $k_7 = x_7 W_K$, $v_7 = x_7 W_V$ (all shape $1 imes 4$).
  • KV Concatenation: $K_{ ext{all}} = [K_{ ext{cache}} \,;\, k_7] \implies 7 imes 4$.
  • Attention Vector: $S_{ ext{decode}} = q_7 K_{ ext{all}}^T \implies (1 imes 4) imes (4 imes 7) = \mathbf{1 imes 7}$.
  • Token 7 Output: $ ext{Output}_7 = ext{Softmax}\left( rac{S_{ ext{decode}}}{\sqrt{d}} ight) V_{ ext{all}} \implies (1 imes 7) imes (7 imes 4) = \mathbf{1 imes 4}$.

GPU Architecture & SM Concurrency

Inside the GPU, matrix multiplications are partitioned into tiles and assigned to thread blocks across multiple Streaming Multiprocessors (SMs).
