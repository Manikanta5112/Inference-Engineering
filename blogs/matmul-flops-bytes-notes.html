03Counting the FLOPs

Each output cell needs d multiplications and d−1 additions - call it 2d, we drop the −1, it doesn't matter at any real scale. There are n·d output cells total.

flops per output cell = 2d = 2 × 3 = 6
number of output cells = n × d = 2 × 3 = 6
total flops = 2d × nd = 2nd² = 2 × 2 × 9 = 36 FLOPs

04Counting the bytes - this is the part that wasn't clicking

The confusion last time was this: X and W elements get used many times each (once per output that needs them), but they only need to be fetched from HBM once - a decent kernel keeps the on-chip copy around and reuses it instead of re-fetching. So "bytes moved" counts distinct elements, not uses.

Hover-equivalent: each cell below is tagged with how many outputs it feeds into - that's the reuse count, and it's exactly why we only charge one HBM trip per element.

X - read once each
W - read once each
O - written once each

the little red numbers = how many output cells reuse that element on-chip, before it's evicted

elements of X = n·d = 2×3 = 6 (each reused d=3 times, fetched once)
elements of W = d·d = 3×3 = 9 (each reused n=2 times, fetched once)
elements of O = n·d = 2×3 = 6 (written once, never re-read here)
total elements moved = 2nd + d² = 12 + 9 = 21
bytes (fp16, p=2 bytes) = p(2nd + d²) = 2 × 21 = 42 bytes
the min. bytes formula assumes the kernel is smart about reuse - a lazy kernel that re-fetches on every use would move way more than 42 bytes here

05Arithmetic intensity - FLOPs per byte

Divide what you just computed: 36 FLOPs / 42 bytes ≈ 0.86 FLOPs per byte. That single number tells you whether the GPU's math units or its memory bus is the bottleneck for this exact operation.

AI = FLOPs / bytes = 2nd² / [ p(2nd + d²) ]
AI = 36 / 42 = ≈ 0.86 FLOPs/byte

Play with n below (d and precision fixed) and watch that ratio move - this is the whole "batching helps throughput" argument from earlier, made concrete.

n=1 (decoding one token) sits deep in memory-bound territory - you pay for the whole weight matrix to produce almost no math. Push n up (bigger batch, longer prefill) and intensity climbs toward its ceiling of d/p, because the same loaded weight tile gets reused across more rows before eviction.
