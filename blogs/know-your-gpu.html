00 — First principles

A CPU has few, powerful workers. A GPU has thousands of small ones.

A CPU core is built to run one complex, branchy sequence of instructions as fast as possible — big caches, aggressive out-of-order execution, branch prediction. A GPU core is built to do one simple operation, repeated across enormous amounts of data at once. Matrix multiply, the operation behind almost all deep learning, is exactly that: the same multiply-add, over and over, on different numbers. That's why GPUs trade a few fast cores for thousands of small, simple ones.

CPU

~8–64 large, general-purpose cores. Each one is great at running a different, complicated task.

optimized for: latency of one task

GPU

Thousands of small cores, grouped so they all execute the same instruction on different data, simultaneously.

optimized for: throughput across many tasks

04 — The recap

Where the data lives while all this happens

Every core above pulls its operands from the same nested memory system: registers (private to a thread, inside the partition) → L1 / shared memory (the 256KB block you just clicked, shared by the whole SM) → L2 (shared by every SM on the chip) → HBM/VRAM (the whole 80GB+ pool, off-chip). Small and fast near the cores, huge and slow far from them — the entire performance story of a GPU kernel is how well it reuses data at the small-fast end before it has to go back to the big-slow end.
