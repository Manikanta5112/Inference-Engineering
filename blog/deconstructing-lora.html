Deconstructing LoRA: From Standard Attention to Multi-Tenant Serving

A step-by-step breakdown of low-rank adaptation, parameter arithmetic, and zero-latency serving.

Fine-tuning large language models on downstream tasks is notoriously compute- and storage-heavy. Full parameter fine-tuning modifies every single weight in a network, creating enormous memory footprints during optimization and unwieldy artifacts in production.

Low-Rank Adaptation (LoRA) bypassed this limitation with a simple premise: the change in weights during adaptation resides on a low-rank subspace. Let's trace how that works mathematically, step by step - from basic linear projections to matrix factorization, scaling dynamics, and production deployments.

1. The Starting Point: Standard Attention Projections

Let's ground the math in a concrete transformer block. Suppose an input matrix X contains 3 token representations, each with an embedding dimension d = 4:

X ∈ ℝ^(3 × 4)

In standard multi-head self-attention, input tokens project into Query (Q), Key (K), and Value (V) spaces using independent projection matrices W_Q, W_K, and W_V:

Q = X · W_Q    ──►   (3 × 4) × (4 × 4) = (3 × 4)
K = X · W_K    ──►   (3 × 4) × (4 × 4) = (3 × 4)
V = X · W_V    ──►   (3 × 4) × (4 × 4) = (3 × 4)

In full fine-tuning, every single entry in W_Q is updated via gradient descent:

W_new = W_0 + ΔW (where ΔW ∈ ℝ^(4 × 4))

This means computing and storing gradients and optimizer states for all 16 values per projection matrix.

2. Factorizing the Weight Update (ΔW = B · A)

LoRA freezes the base matrix W_0 completely (requires_grad = False) and decomposes the update matrix ΔW into two thin, low-rank matrices B and A:

ΔW = B · A

Setting a rank bottleneck r = 1 on our (4 × 4) projection:

  • Matrix A (Down-projection): Shape (r × d) = (1 × 4)
  • Matrix B (Up-projection): Shape (d × r) = (4 × 1)
Input X [3 × 4] ──────┬───► [ Frozen Base W_0 ] ─────────► [3 × 4]
                      │                                      │
                      └───► [ A (1 × 4) ] ──► [ B (4 × 1) ] ─► [3 × 4] ──(+)──► Output Q [3 × 4]
                             (Down-project)   (Up-project)

Instead of 16 trainable weights, we only optimize (4 × 1) + (1 × 4) = 8 parameters. As embedding dimensions grow to production sizes (e.g., d = 4096), this compression factor reaches several hundred-fold.

3. Scaling Up: Attention Dimension vs. MLP Dimension

In real architectures like Llama or GPT-style models, d = 4096 represents the embedding dimension (often written as d_model or hidden_size). A common point of confusion is why projection layers are 4096 × 4096 rather than expanded by 4×.

A standard transformer block splits into two primary sub-layers with different dimensions:

Sub-Layer Matrix Names Projection Shape (d = 4096)
Attention W_Q, W_K, W_V, W_O d ──► d 4096 × 4096
Feed-Forward (MLP) W_up / W_gate d ──► 4d 4096 × 16384
Feed-Forward (MLP) W_down 4d ──► d 16384 × 4096

LoRA was originally introduced targeting the attention projections (W_Q, W_V), which map d → d. For d = 4096 and rank r = 8:

Full Update:  4096 × 4096 = 16,777,216 parameters
LoRA Update:  (4096 × 8) + (8 × 4096) = 65,536 parameters
Reduction:    ~256× fewer trainable weights per matrix

4. The Forward Pass & The Role of α and r

During adaptation, the modified forward pass is defined as:

h = W_0 · x + (α / r) · (B · A · x)

Two hyperparameters govern the low-rank path:

                      r = 8 (Inner Dimension)
                       ┌─┐
                       │ │
            d = 4096   │B│   ×   ┌───────────┐  r = 8
                       │ │       └───────────┘
                       │ │         d = 4096
                       └─┘            A
                    (4096 × 8)    (8 × 4096)
                         │            │
                         └──────┬─────┘
                                ▼
                             B · A  ───► Scaled by (α / 8)
                          (4096 × 4096)

Rank (r): The Capacity Dial

The rank r defines the inner dimension of the factorization. It caps the degrees of freedom available for the update. Lower values (4, 8, 16) prevent overfitting and reduce adapter footprints; higher values allow the adapter to absorb more complex domain shifts.

Alpha (α): The Update Scale

Because matrix multiplication (B · A) calculates the dot product across the inner dimension r, expanding r increases the natural magnitude of activations. Scaling the product by α / r decouples capacity from learning rate tuning:

  • Scaling (α / r): α is a constant (e.g., 16 or 32). Scaling the update helps stabilize hyperparameters when you change rank r.
  • You can experiment with changing r = 8 to r = 32 without needing to readjust learning rates from scratch.
  • By convention, setting α = 2r (e.g., r = 8, α = 16) delivers a stable baseline across popular fine-tuning frameworks.
Safe Initialization: Matrix A is initialized with Gaussian noise 𝒩(0, σ²), and matrix B is initialized to zeros. At step 0, ΔW = B · A = 0, guaranteeing the model begins training with its exact pre-trained baseline behavior.

5. Choosing What to Adapt: target_modules in Practice

In both Hugging Face PEFT and Unsloth, the weights that get decomposed are controlled by the target_modules argument. However, their defaults and common conventions differ.

Default Behavior Comparison

Framework Default target_modules (if omitted) What Actually Gets Decomposed
Hugging Face (PEFT) Model-specific defaults (e.g., ["q_proj", "v_proj"] for LLaMA/Mistral) Only Attention Query & Value (W_q, W_v)
Unsloth Explicitly presets all 7 core linear modules All 4 Attention + 3 MLP layers

The 7 Target Modules in Modern LLMs (LLaMA, Mistral, Qwen)

Modern autoregressive models split a Transformer layer into Self-Attention and a SwiGLU Feed-Forward Network (FFN). When decomposing "all linear layers," all 7 of these matrices receive their own independent A and B adapter pairs:

Self-Attention Projections (4 matrices):

  • q_proj (W_q): Query projection
  • k_proj (W_k): Key projection
  • v_proj (W_v): Value projection
  • o_proj (W_o): Output/dense projection

SwiGLU MLP / FFN Projections (3 matrices):

  • gate_proj (W_gate): Computes the gating mechanism SiLU(x W_gate)
  • up_proj (W_up): Expands the hidden state to intermediate FFN dimension
  • down_proj (W_down): Projects the intermediate FFN state back down to d_model

How You Configure Them in Code

Hugging Face PEFT (LoraConfig): to avoid PEFT's minimal W_q, W_v default and target everything:

from peft import LoraConfig

# Recommended: target all linear layers automatically
config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules="all-linear",  # Or: ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

Unsloth (FastLanguageModel.get_peft_model): explicitly requires/sets all 7 layers by default for best convergence:

model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_alpha=16,
    lora_dropout=0,  # Optimized to 0 in Unsloth
    bias="none",
)

What Is Excluded?

Even when using "all-linear", the following are frozen and not decomposed by default:

  • Embedding Layer (embed_tokens): Adapting this consumes massive VRAM because vocab size is huge (e.g., 128k × 4096).
  • Language Model Head (lm_head): Projects final hidden states to vocab logits. Only targeted if adding new tokens or explicitly using modules_to_save=["lm_head", "embed_tokens"].
  • Normalization Layers (RMSNorm / LayerNorm): Kept frozen.

6. Training VRAM vs. Production Serving Realities

Why do full fine-tunes require over 100 GB of VRAM to train, but only 14 GB to store?

During training with mixed-precision FP16 and AdamW, optimizer overhead scales drastically:

  • Model Weights (FP16): 2 bytes/param
  • Gradients (FP16): 2 bytes/param
  • AdamW Momentum (FP32): 4 bytes/param
  • AdamW Variance (FP32): 4 bytes/param
  • Master Weights (FP32): 4 bytes/param
  • Total Training Footprint: ~16 bytes per parameter (~112 GB VRAM for a 7B model)

Once training concludes, optimizer states and gradients are discarded. The saved checkpoint requires only 2 bytes/parameter = 14 GB.

7. Multi-Tenant Serving Architecture

If you maintain 5 separate full-finetune models, you must store and load 5 × 14 GB = 70 GB of static checkpoints. Serving them simultaneously requires dedicated GPU allocations for each copy.

With LoRA, the base model stays frozen in VRAM once, and lightweight task adapters (20-50 MB each) are dynamically attached per incoming request:

Incoming Query ──► [ Request Router ]
                         │
                         ├── (Task: SQL)     ──► [ Base Model (14 GB) ] + [ SQL Adapter (30 MB) ]
                         ├── (Task: Medical) ──► [ Base Model (14 GB) ] + [ Med Adapter (30 MB) ]
                         └── (Task: Support) ──► [ Base Model (14 GB) ] + [ Support Adapter (30 MB) ]

When deploying a single dedicated endpoint, the weights can be permanently fused back together prior to export:

W_deployed = W_0 + (α / r) · (B · A)

This merges the low-rank delta directly into the base matrix, yielding standard model dimensions with zero added inference latency.
