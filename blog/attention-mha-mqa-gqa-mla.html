Understanding the Evolution of Attention: MHA, MQA, GQA, and MLA

A complete mathematical and visual walkthrough of how modern transformer architectures solve the memory bandwidth bottleneck in large language models.

1. The Core Bottleneck: Why We Need New Attention Variants

When deploying Large Language Models (LLMs) at scale, the primary performance bottleneck during token generation (autoregressive decoding) is memory bandwidth, not compute throughput (FLOPs).

To generate each new token, the model needs the Key and Value representations of all previous tokens. Storing these representations in GPU memory is known as the KV Cache. As context windows expand to 32k, 128k, or 1M tokens, the KV cache becomes enormous, quickly exhausting High Bandwidth Memory (HBM) and causing memory-bound latency.

$$\text{KV Cache Size (Bytes)} = 2 \times B \times L \times N_{\text{layers}} \times H_{KV} \times d_k \times P$$

Breaking Down the Parameters:

  • 2: Storing both the Key matrix ($K$) and Value matrix ($V$).
  • $B$ (Batch Size): Number of independent prompt sequences processed concurrently.
  • $L$ (Sequence / Context Length): Total tokens in prompt + generated so far.
  • $N_{\text{layers}}$: Number of Transformer layers in the network.
  • $H_{KV}$: Number of Key-Value heads allocated.
  • $d_k$: Dimension of each attention head (often $d_{\text{model}} / H_Q$).
  • $P$: Precision in bytes (e.g., 2 bytes for FP16/BF16, 1 byte for FP8).

2. Multi-Query Attention (MQA): The Minimalist Approach

In standard Multi-Head Attention (MHA), every Query head has its own Key and Value head. In Multi-Query Attention (MQA), all $H_Q$ Query heads share a single Key and Value head.

Mathematical Walkthrough with Concrete Dimensions

Let's trace the operations with a concrete input matrix:

  • Input sequence: $X \in \mathbb{R}^{3 \times 4}$ (Sequence length $N = 3$, embedding dimension $d_{\text{in}} = 4$).
  • 2 Query Heads: $W_{Q1}, W_{Q2} \in \mathbb{R}^{4 \times 2}$.
  • Shared Key & Value: $W_K, W_V \in \mathbb{R}^{4 \times 2}$ (Head dimension $d_k = 2$).

Step 1: Projections

$Q_1 = X W_{Q1} \in \mathbb{R}^{3 \times 2}$  |  $Q_2 = X W_{Q2} \in \mathbb{R}^{3 \times 2}$

$K = X W_K \in \mathbb{R}^{3 \times 2}$  |  $V = X W_V \in \mathbb{R}^{3 \times 2}$ (Shared across both heads)

Step 2: Attention Computation per Head

Head 1:

$$S_1 = Q_1 K^T \in \mathbb{R}^{3 \times 3} \implies A_1 = \text{softmax}\left(\frac{S_1}{\sqrt{2}}\right) \implies O_1 = A_1 V \in \mathbb{R}^{3 \times 2}$$

Head 2:

$$S_2 = Q_2 K^T \in \mathbb{R}^{3 \times 3} \implies A_2 = \text{softmax}\left(\frac{S_2}{\sqrt{2}}\right) \implies O_2 = A_2 V \in \mathbb{R}^{3 \times 2}$$

Step 3: Concatenation and Final Projection

We concatenate both output context vectors and project using $W_O \in \mathbb{R}^{4 \times 4}$:

$$O_{\text{concat}} = [O_1, O_2] \in \mathbb{R}^{3 \times 4} \implies O = O_{\text{concat}} W_O \in \mathbb{R}^{3 \times 4}$$
Key Insight on Perspectives vs. Tradeoff:
Even though $K$ and $V$ are shared, each Query head still retains its own unique perspective because $Q_1 \neq Q_2$ yields different attention weight distributions ($A_1 \neq A_2$). However, because the Value vectors are identical, model expressivity suffers slightly.

3. Grouped-Query Attention (GQA): The Golden Mean

Grouped-Query Attention interpolates between MHA and MQA by partitioning $H_Q$ query heads into $G$ groups. Each group shares its own dedicated $(K_g, V_g)$ pair.

GQA Derivation ($H_Q = 4, G = 2$)

Assume 4 Query heads grouped into 2 pairs ($G_1 = \{Q_1, Q_2\}, G_2 = \{Q_3, Q_4\}$):

Group 1 Projections & Computations (using $K_1, V_1$):

$$O_1 = \text{softmax}\left(\frac{Q_1 K_1^T}{\sqrt{d_k}}\right) V_1 \in \mathbb{R}^{3 \times 2} \quad \text{and} \quad O_2 = \text{softmax}\left(\frac{Q_2 K_1^T}{\sqrt{d_k}}\right) V_1 \in \mathbb{R}^{3 \times 2}$$

Group 2 Projections & Computations (using distinct $K_2, V_2$):

$$O_3 = \text{softmax}\left(\frac{Q_3 K_2^T}{\sqrt{d_k}}\right) V_2 \in \mathbb{R}^{3 \times 2} \quad \text{and} \quad O_4 = \text{softmax}\left(\frac{Q_4 K_2^T}{\sqrt{d_k}}\right) V_2 \in \mathbb{R}^{3 \times 2}$$

Final Output:

$$O = [O_1, O_2, O_3, O_4] W_O \in \mathbb{R}^{3 \times 4} \quad \text{where } W_O \in \mathbb{R}^{8 \times 4}$$

Why GQA is Not Just MQA Repeated

A common point of confusion is thinking GQA and MQA cache the same data. They do not:

  • MQA keeps 1 database of Keys and Values in VRAM. Every query head searches the same book.
  • GQA (e.g. 8 groups) keeps 8 distinct databases in VRAM. Group 1 searches a "Syntax" book while Group 2 searches a "Semantics" book.

4. Multi-Head Latent Attention (MLA): DeepSeek's Breakthrough

While GQA achieves significant savings, models like DeepSeek-V2 and DeepSeek-V3 introduce Multi-Head Latent Attention (MLA). Instead of just reducing the number of heads, MLA uses low-rank matrix compression on the hidden representation directly.

How MLA Works:

  1. Low-Rank Down-Projection: The input vector $h_t$ is compressed into a low-dimensional latent vector $\mathbf{c}_t^{KV}$:
    $$\mathbf{c}_t^{KV} = h_t W_{DKV} \in \mathbb{R}^{d_c} \quad (d_c \ll d_{\text{model}})$$
  2. Latent Caching: During autoregressive generation, only this small latent vector $\mathbf{c}_t^{KV}$ is stored in the KV cache, completely eliminating the need to store full $K$ and $V$ heads.
  3. Query-Side Matrix Absorption: Rather than reconstructing $K$ and $V$ via up-projection matrices during inference, the up-projection weight $W_{UK}$ is mathematically absorbed into the Query projection:
    $$Q (c^{KV} W_{UK})^T = (Q W_{UK}^T) (c^{KV})^T$$
    This allows computing attention scores directly against the compressed latent vector!
  4. Decoupled RoPE Key: Because Rotary Position Embeddings (RoPE) are non-linear and cannot be linearly absorbed, MLA introduces a small separate head for positional encoding:
    $$\text{Cached per token} = [\mathbf{c}_t^{KV} \in \mathbb{R}^{d_c}, \; \mathbf{k}_t^R \in \mathbb{R}^{d_R}]$$

Exact Memory Reduction Ratio Derivation

Let's compare the per-token KV cache memory between MHA and MLA:

$$\text{MHA Cache per token} = 2 \times d_{\text{model}}$$ $$\text{MLA Latent Cache per token} = d_{\text{latent}}$$
The Exact Savings Multiplier:
$$\text{Savings Factor} = \frac{\text{MHA Cache Size}}{\text{MLA Cache Size}} = \frac{2 \times d_{\text{model}}}{d_{\text{latent}}}$$

Notice the factor of 2 in the numerator: MHA stores two full matrices ($K$ and $V$), whereas MLA stores one compressed latent vector. For example, with $d_{\text{model}} = 4096$ and $d_{\text{latent}} = 512$:

$$\text{Savings Factor} = \frac{2 \times 4096}{512} = 16\times \text{ memory reduction!}$$

5. Architectural Comparison Matrix

6. Summary & Takeaways

  • MHA is expressive but suffers from severe memory bandwidth bottlenecks due to storing independent $K, V$ heads for every Query head.
  • MQA minimizes cache size by sharing a single $(K, V)$ pair across all heads, achieving maximum throughput at the cost of slight capacity loss.
  • GQA balances this trade-off by grouping query heads around several $(K, V)$ pairs (standard in LLaMA-2/3, Mistral).
  • MLA redefines cache efficiency by projecting representations into a low-rank latent space, absorbing weights via matrix algebra during decoding and achieving MHA-level representation with MQA-level cache footprints.
