02

Phase 1 - Prefill

Prompt processing

The entire prompt is processed in one shot. Every token's query, key, and value vector is produced by the same batched matrix multiply, and every token attends to every other token simultaneously.

Fig 1 - Prefill dataflow
$$Q = XW_Q,\quad K = XW_K,\quad V = XW_V \;\rightarrow\; (6\times4)\times(4\times4) = 6\times4$$
$$S = QK^{\mathsf T} \;\rightarrow\; (6\times4)\times(4\times6) = 6\times6$$
Cell (i, j) - how much token i attends to token j.
$$A = \mathrm{Softmax}\!\left(\frac{S}{\sqrt d}\right) \quad (6\times6), \qquad \mathrm{Output} = AV \;\rightarrow\; (6\times6)\times(6\times4) = 6\times4$$
Row-wise softmax; result is context-enriched representations for all 6 tokens.
03

Hardware Mapping

Inside the Streaming Multiprocessors

A modern GPU packs dozens of Streaming Multiprocessors (SMs), each with its own shared memory / L1 cache, warp schedulers, CUDA cores, and Tensor Cores.

Fig 2 - Memory hierarchy → SM tiling
  • Tiling & thread blocks - the 6×4 and 4×4 operations split into 2D tiles; thread blocks land on different SMs across the chip.
  • True hardware concurrency - separate SMs execute arithmetic on separate matrix tiles in the same clock cycles.
  • Tensor Core utilization - MMA instructions load sub-matrices straight into Tensor Core registers to run dot products in parallel.
  • Execution profile: compute-bound - the 6×4×4 matrix–matrix multiplies carry high arithmetic intensity, keeping Tensor Cores saturated.

Phase 2 - Autoregressive Decode

Generating token #7

Once prefill finishes, generation turns sequential. To produce token #7, only the newly generated token needs projecting - everything before it is already sitting in the KV cache.

Fig 3 - Decode-step dataflow
$$q_7 = x_7W_Q,\quad k_7 = x_7W_K,\quad v_7 = x_7W_V \;\rightarrow\; (1\times4)\times(4\times4) = 1\times4$$
$$K_{\text{all}} = \begin{bmatrix}K_{\text{cached}}\\ k_7\end{bmatrix}\ (7\times4), \qquad V_{\text{all}} = \begin{bmatrix}V_{\text{cached}}\\ v_7\end{bmatrix}\ (7\times4)$$
k₇ and v₇ append to the existing cache rather than recomputing tokens 1–6.
$$S_{\text{decode}} = q_7K_{\text{all}}^{\mathsf T} \;\rightarrow\; (1\times4)\times(4\times7) = 1\times7$$ $$\mathrm{Output}_7 = \mathrm{Softmax}\!\left(\frac{S_{\text{decode}}}{\sqrt d}\right)V_{\text{all}} \;\rightarrow\; (1\times7)\times(7\times4) = 1\times4$$
Why decode feels slow Every single generated token drags the full weight matrices and the entire KV cache across the memory bus - for one row of arithmetic. Low arithmetic intensity per byte moved is the whole story.
