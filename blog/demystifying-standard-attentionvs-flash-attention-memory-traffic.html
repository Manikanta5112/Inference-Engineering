Memory Traffic Analysis: Standard Attention vs. FlashAttention-2

A step-by-step breakdown of data movement between GPU High-Bandwidth Memory (HBM) and On-Chip Shared Memory (SRAM).

1. Core Parameters & Notation

Before diving into memory movement, let us define the key mathematical and hardware parameters involved in transformer attention layers:

Parameter Description Typical Values / Formula
$N$ Sequence length (number of input tokens) $2048, 4096, 8192, \dots$
$d$ Head dimension / embedding dimension per head $64, 128$
$M$ Fast on-chip SRAM capacity per SM $100\text{ KB} - 228\text{ KB}$
$B_r$ Query block row size loaded into SRAM $B_r = \min\left(\left\lceil \frac{M}{4d} \right\rceil, d\right) \approx 64 \text{ or } 128$
$B_c$ Key/Value block column size loaded into SRAM $B_c = \left\lceil \frac{M}{4d} \right\rceil \approx 64 \text{ or } 128$
$T_r$ Total number of Query blocks $T_r = \left\lceil \frac{N}{B_r} \right\rceil$
$T_c$ Total number of Key/Value blocks $T_c = \left\lceil \frac{N}{B_c} \right\rceil$

2. FlashAttention-2 Memory Traffic Table

In FlashAttention-2, the outer loop iterates over Query blocks ($Q$), while the inner loop iterates over Key/Value blocks ($K, V$). The full $N \times N$ intermediate attention matrices ($S, P$) are computed and accumulated purely in SRAM without touching HBM.

Step Read (HBM → SRAM) Compute (Inside SRAM) Write (SRAM → HBM)
1. Load Query Block $Q_i \in \mathbb{R}^{B_r \times d}$ - 0 (No write)
2. Stream $K, V$ Blocks $K_j, V_j \in \mathbb{R}^{B_c \times d}$ $S_{ij} = Q_i K_j^T \in \mathbb{R}^{B_r \times B_c}$ 0 (Kept in SRAM)
3. Online Softmax 0 (Already in SRAM) $P_{ij} = \text{softmax}(S_{ij}) \in \mathbb{R}^{B_r \times B_c}$ 0 (Kept in SRAM)
4. Accumulate Output 0 (Already in SRAM) $O_i = O_i + P_{ij} V_j \in \mathbb{R}^{B_r \times d}$ 0 (Accumulated in SRAM)
5. Store Output - Final rescaling of $O_i$ $O_i \in \mathbb{R}^{B_r \times d}$
6. Store Stats (Backward) - $L_i \in \mathbb{R}^{B_r}$ (LogSumExp) $L_i \in \mathbb{R}^{B_r}$

3. Clarifying Tile vs. Block Dimensions & K/V Traffic

A common point of confusion when analyzing FlashAttention is how tiles are dimensioned and why the total traffic for $K$ and $V$ is $2 \frac{N^2 d}{B_r}$:

Terminology Note: "Tile" vs. "Block"

In GPU literature and FlashAttention papers, Tile and Block mean the exact same thing: a sub-matrix slice ($B_r \times d$ or $B_c \times d$) loaded into fast on-chip SRAM.

1. Dimension of a Single Tile (Chunk)

When loading a single Key or Value tile into on-chip SRAM:

  • Tile length (row count) = $B_c$
  • Embedding / head dimension (column count) = $d$
  • Elements in a single tile of $K$ and $V$: $(B_c \times d) + (B_c \times d)$

2. Streaming All Tiles Across One Pass

To sweep through the entire sequence of length $N$ in the inner loop:

  • Number of column tiles = $\frac{N}{B_c}$
  • Total elements in one complete pass: $$\left(\frac{N}{B_c}\right) \times (B_c \times d) = N \times d$$

The tile size $B_c$ cancels out. One full pass across all column tiles loads exactly $N \times d$ elements of $K$ and $N \times d$ elements of $V$.

3. Total Memory Traffic Across the Outer Loop

In FlashAttention-2, the outer loop repeats for every single Query tile $Q_i$:

  • Total number of Query tiles = $\frac{N}{B_r}$ (where $B_r$ is the query tile length).
  • For each Query tile, the inner loop streams the entire sequence of $K$ and $V$ from HBM to SRAM:
$$\text{Total Read Traffic for } K, V = \underbrace{\left(\frac{N}{B_r}\right)}_{\text{Number of Q tiles}} \times \underbrace{\Big[(N \times d) + (N \times d)\Big]}_{\text{Full K and V sequence per pass}} = 2 \left(\frac{N^2 d}{B_r}\right)$$

Why is $\left(\frac{N}{\text{tile\_length}}\right) \times d$ not the tile size? Because $\frac{N}{\text{tile\_length}}$ represents the count of tiles (a dimensionless number), while each loaded slice has dimension $\text{tile\_length} \times d$.

4. Mathematical Derivation of Total Memory Traffic

FlashAttention-2 Read Traffic

  • Read $Q$: Each query block is loaded into SRAM once in the outer loop: $$\text{Reads}_{Q} = T_r \cdot (B_r \cdot d) = N \cdot d$$
  • Read $K$ and $V$: For every outer query block ($T_r$ iterations), all $T_c$ blocks of $K$ and $V$ are streamed: $$\text{Reads}_{K, V} = 2 \cdot T_r \cdot \sum_{j=1}^{T_c} (B_c \cdot d) = 2 \cdot T_r \cdot (N \cdot d) = 2 \cdot \left(\frac{N}{B_r}\right) \cdot N d = 2 \frac{N^2 d}{B_r}$$
$$\text{Total HBM Reads} = Nd + 2\left(\frac{N^2 d}{B_r}\right)$$

FlashAttention-2 Write Traffic

  • Write $O$: Output matrix $O$ is written once per query block when inner accumulation completes: $$\text{Writes}_{O} = T_r \cdot (B_r \cdot d) = N \cdot d$$
  • Write Softmax Stats ($L$): Log-sum-exp values written for backward pass: $$\text{Writes}_{L} = T_r \cdot B_r = N$$
$$\text{Total HBM Writes} = Nd + N$$

Substituting $B_r$ Back In

The $\frac{N^2 d}{B_r}$ term still has a block size hiding inside it. Section 1 fixed $B_r \approx \frac{M}{4d}$, so it's not a free variable, it's itself inversely proportional to $d$. Substituting it in is what turns a single $d$ into $d^2$:

$$\frac{N^2 d}{B_r} = \frac{N^2 d}{\;\frac{M}{4d}\;} = N^2 d \cdot \frac{4d}{M} = \frac{4 N^2 d^2}{M}$$

So the read term $2 \cdot \frac{N^2 d}{B_r}$ becomes $\frac{8 N^2 d^2}{M}$, and that's exactly the $\frac{N^2 d^2}{M}$ sitting inside the $\mathcal{O}(\cdot)$ below - it isn't a new quantity, it's $\frac{N^2 d}{B_r}$ after $B_r$ is written in terms of $M$ and $d$.

Total FlashAttention-2 HBM Traffic Summary

$$\text{Total Traffic} = 2Nd + N + 2\left(\frac{N^2 d}{B_r}\right) = 2Nd + N + \frac{8N^2d^2}{M} = \mathcal{O}\left(Nd + \frac{N^2 d^2}{M}\right)$$

5. FlashAttention in Practice: A Worked Step-by-Step Walkthrough

To see how FlashAttention executes without ever writing large intermediate matrices to High Bandwidth Memory (HBM), let's trace a concrete numerical example.

We have a sequence length $N = 16$ and embedding dimension $d = 8$, tiled into blocks of $4 \times 8$:

  • Queries: $Q_1, Q_2, Q_3, Q_4 \in \mathbb{R}^{4 \times 8}$
  • Keys: $K_1, K_2, K_3, K_4 \in \mathbb{R}^{4 \times 8}$
  • Values: $V_1, V_2, V_3, V_4 \in \mathbb{R}^{4 \times 8}$

We will trace the execution of Thread Block 1, which computes the output for the first tile of tokens: $Q_1$.

Step 0: Initialization in On-Chip SRAM

Thread Block 1 loads the tile $Q_1$ $(4 \times 8)$ from slow HBM into fast SRAM and allocates three small tracking buffers in SRAM:

  • Running Maximum ($m$): Vector of size $4$ initialized to $[-\infty, -\infty, -\infty, -\infty]$. Tracks the max logit seen so far per row for numerical stability.
  • Running Exponential Sum ($\ell$): Vector of size $4$ initialized to $[0, 0, 0, 0]$. Tracks the denominator of the softmax.
  • Output Accumulator ($O_1$): Matrix of shape $(4 \times 8)$ initialized to all zeros ($\mathbf{0}$).
Why this matters

These statistics take negligible SRAM memory ($4 + 4 + 32$ floats) and remain entirely on-chip.

Step 1: Iteration 1 - Streaming Key/Value Tile 1 ($K_1, V_1$)

  1. Load $K_1, V_1$ into SRAM: SRAM now holds $Q_1$, $K_1$, and $V_1$ (each shape $4 \times 8$).
  2. Compute Partial Attention Scores:
    $$S_{11} = \frac{Q_1 K_1^T}{\sqrt{d}} \in \mathbb{R}^{4 \times 4}$$

    Let's trace Row 1 of $S_{11}$. Suppose its scores are:

    $$\text{Row 1 scores} = [2.0, 4.0, 1.0, 3.0]$$
  3. Update Running Max ($m$):
    • Tile max for Row 1: $\tilde{m}_1 = \max(2.0, 4.0, 1.0, 3.0) = 4.0$
    • New running max: $m_{\text{new}} = \max(m_{\text{old}}, \tilde{m}_1) = \max(-\infty, 4.0) = 4.0$
  4. Compute Exponentials & Unnormalized Weights:
    $$P_{11} = \exp(S_{11} - m_{\text{new}}) = [\exp(2 - 4), \exp(4 - 4), \exp(1 - 4), \exp(3 - 4)] = [e^{-2}, e^0, e^{-3}, e^{-1}] \approx [0.135, 1.0, 0.050, 0.368]$$
  5. Accumulate into Output & Sum:
    • Tile exponential sum: $\tilde{\ell}_1 = 0.135 + 1.0 + 0.050 + 0.368 = 1.553$
    • Running sum update: $\ell = \ell_{\text{old}} \cdot e^{m_{\text{old}} - m_{\text{new}}} + \tilde{\ell}_1 = 0 + 1.553 = 1.553$
    • Output accumulator update:
      $$O_1 = P_{11} V_1 \quad (\text{shape } 4 \times 8)$$

Step 2: Iteration 2 - Streaming Key/Value Tile 2 ($K_2, V_2$)

$K_1$ and $V_1$ are discarded from SRAM. The block loads $K_2$ and $V_2$ into those same memory slots.

  1. Compute New Scores:
    $$S_{12} = \frac{Q_1 K_2^T}{\sqrt{d}} \in \mathbb{R}^{4 \times 4}$$

    Suppose Row 1 of $S_{12}$ yields higher scores:

    $$\text{Row 1 scores} = [5.0, 1.0, 6.0, 2.0]$$
  2. Update Running Max ($m$):
    • Tile max for Row 1: $\tilde{m}_2 = \max(5.0, 1.0, 6.0, 2.0) = 6.0$
    • New running max: $m_{\text{new}} = \max(m_{\text{old}}, \tilde{m}_2) = \max(4.0, 6.0) = 6.0$
  3. Rescale Prior Accumulators (The Core Online Softmax Magic):

    Because our maximum increased from $4.0$ to $6.0$, the previous accumulators were scaled by $e^{x - 4.0}$ instead of $e^{x - 6.0}$. We correct them by multiplying by $e^{m_{\text{old}} - m_{\text{new}}} = e^{4.0 - 6.0} = e^{-2} \approx 0.135$:

    $$\ell_{\text{rescaled}} = \ell_{\text{old}} \cdot e^{-2} = 1.553 \cdot 0.135 \approx 0.210$$
    $$O_{1, \text{rescaled}} = O_1 \cdot e^{-2}$$
  4. Compute New Exponentials & Add:
    $$P_{12} = \exp(S_{12} - 6.0) = [e^{-1}, e^{-5}, e^0, e^{-4}] \approx [0.368, 0.007, 1.0, 0.018]$$
    $$\tilde{\ell}_2 = 0.368 + 0.007 + 1.0 + 0.018 = 1.393$$
    $$\ell_{\text{new}} = \ell_{\text{rescaled}} + \tilde{\ell}_2 = 0.210 + 1.393 = 1.603$$
    $$O_1 = O_{1, \text{rescaled}} + P_{12} V_2$$

Step 3: Iterations 3 & 4 - Streaming $(K_3, V_3)$ and $(K_4, V_4)$

The loop repeats identically for the remaining tiles:

  • Load $(K_3, V_3) \rightarrow$ compute $S_{13} \rightarrow$ update $m \rightarrow$ rescale $O_1, \ell \rightarrow$ accumulate $P_{13} V_3$.
  • Load $(K_4, V_4) \rightarrow$ compute $S_{14} \rightarrow$ update $m \rightarrow$ rescale $O_1, \ell \rightarrow$ accumulate $P_{14} V_4$.

Step 4: Final Normalization & HBM Write

After processing all $4$ key/value tiles, the output accumulator $O_1$ holds the exact unnormalized dot products scaled by the global maximum:

$$O_1 = \sum_{j=1}^4 e^{S_{1j} - m_{\text{global}}} V_j, \quad \ell = \sum_{j=1}^4 \sum \exp(S_{1j} - m_{\text{global}})$$
  1. Normalize in SRAM:
    $$O_{1, \text{final}} = \text{diag}(\ell)^{-1} O_1 \quad (\text{divide each row by its scalar } \ell_i)$$
  2. Write to HBM: Thread Block 1 writes $O_{1, \text{final}} \in \mathbb{R}^{4 \times 8}$ directly back to main GPU memory.
Key Takeaways
  • Zero intermediate $16 \times 16$ allocations: Only sub-blocks of size $4 \times 4$ exist at any point in time, and only inside registers.
  • Exact mathematical equivalence: The rescaling factor $e^{m_{\text{old}} - m_{\text{new}}}$ guarantees that the output matches standard attention bit-for-bit without precision loss or numerical overflow.
  • Massive bandwidth savings: Memory reads/writes drop from $\mathcal{O}(N^2)$ to $\mathcal{O}(N)$, shifting the bottleneck from memory transfer delays to pure Tensor Core computation.

6. Side-by-Side Comparison

Standard Attention

Reads from HBM:

  • $Q, K$: $2 \times Nd$
  • Score $S$: $N^2$
  • Attention $P, V$: $N^2 + Nd$

Writes to HBM:

  • Score $S$: $N^2$
  • Attention $P$: $N^2$
  • Output $O$: $Nd$
Total Traffic:
$4Nd + 4N^2 = \mathcal{O}(Nd + N^2)$
FlashAttention-2

Reads from HBM:

  • Query $Q$: $Nd$
  • Keys & Values $K, V$: $2 \frac{N^2 d}{B_r}$
  • Scores $S, P$: 0 (SRAM only)

Writes to HBM:

  • Output $O$: $Nd$
  • LogSumExp Stats $L$: $N$
  • Scores $S, P$: 0 (SRAM only)
Total Traffic:
$2Nd + N + 2\frac{N^2 d}{B_r} = \mathcal{O}\left(Nd + \frac{N^2 d^2}{M}\right)$

7. Concrete Numerical Example

Let's calculate the exact memory traffic for a realistic transformer configuration:

  • Sequence Length $N = 4096$
  • Head Dimension $d = 64$
  • SRAM Block Size $B_r = 64, B_c = 64$
  • Number of Blocks $T_r = \frac{4096}{64} = 64$
  • Data Type: FP16 (2 bytes per element)
Metric Standard Attention FlashAttention-2 Reduction Factor
Intermediate $S, P$ Traffic $4 \times 4096^2 = 67.11\text{M elements}$ 0 elements ∞ (Eliminated)
$Q, K, V, O$ Vector Traffic $4 \times (4096 \times 64) = 1.05\text{M elements}$ $2Nd + N + 2\frac{N^2 d}{B_r} \approx 34.08\text{M elements}$ -
Total Traffic (Elements) $68.16\text{M elements}$ $34.08\text{M elements}$ ~2.0× speedup
Total Memory Transferred (Bytes) $\approx 136.3\text{ MB}$ $\approx 68.2\text{ MB}$ 50% reduction in I/O

Note: As sequence length $N$ scales to 16k, 32k, or 128k, the $\mathcal{O}(N^2)$ memory traffic reduction grows from $2\times$ to $10\times - 30\times$, vastly outperforming standard attention while saving gigabytes of peak VRAM.
